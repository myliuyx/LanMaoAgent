# 定时任务使用文档

> 本文档描述系统定时任务的配置、任务列表、手动触发方式及日志查看。

---

## 1. 定时任务列表

系统共注册 5 个定时任务，均通过 APScheduler 调度（北京时间）：

| 任务 ID | 名称 | 执行时间 | 执行条件 | 说明 |
|---------|------|---------|---------|------|
| `security_master_sync` | 股票主数据同步 | 周一至周五 18:00 | 无 | 同步全市场股票主数据（名称/行业/状态）到 `dwd_security_master` |
| `daily_stock_sync` | 日线行情同步 | 周一至周五 19:00 | 必须是交易日 | 同步全市场日线行情到 `dwd_stock_daily` |
| `factor_compute` | 技术因子计算 | 周一至周五 20:30 | 必须是交易日 | 计算 MA、RSI、MACD 等指标到 `dwd_stock_factor_daily` |
| `selection_mart` | 选股宽表构建 | 周一至周五 21:30 | 必须是交易日 | 汇总行情+因子+财务到 `mart_stock_selection_daily` |
| `cleanup_logs` | 日志清理 | 每天 00:05 | 无 | 清理 `/app/logs` 下超过 3 天的 `sync_stock_daily_*.log` 文件 |

> **已移除的定时任务**：板块主数据同步 (18:10) 和 股票-板块关系同步 (18:20) 已移除，改为纯手动触发。

**交易日判断**：查询 `dwd_trade_calendar` 表，`is_open = true` 且 exchange = 'SH' 时视为交易日。非交易日自动跳过。

## 2. 定时任务执行流程

每个交易日，数据按以下顺序流转：

```
18:00 股票主数据同步
  └─ 来源: Baostock
  └─ 目标表: dwd_security_master
  └─ 依赖: 无（盘前执行，获取最新股票状态）

19:00 日线行情同步
  └─ 来源: Baostock
  └─ 目标表: dwd_stock_daily
  └─ 依赖: 无

20:30 技术因子计算
  └─ 来源: 基于 dwd_stock_daily 计算
  └─ 目标表: dwd_stock_factor_daily
  └─ 依赖: 日线同步完成

21:30 选股宽表构建
  └─ 来源: dwd_stock_daily + dwd_stock_factor_daily + dwd_stock_financial_indicator + dwd_board_relation
  └─ 目标表: mart_stock_selection_daily
  └─ 依赖: 因子计算完成
```

> **注意**：板块主数据同步和股票-板块关系同步已改为手动触发，见下方接口说明。

## 3. 手动触发接口

所有任务均可以通过 API 手动触发：

### 3.1 日线同步

```bash
POST /api/v1/jobs/sync-daily?trade_date=2026-04-30&force_restart=false
```

- `trade_date`：指定交易日期，不传默认今天
- `force_restart`：true 表示清除断点从头开始

### 3.2 财务指标同步

```bash
POST /api/v1/jobs/sync-financial?year=2026&quarter=1
```

- 指定年份和季度，不传默认当前季度

### 3.3 技术因子计算

```bash
POST /api/v1/jobs/sync-factor?trade_date=2026-04-30&full=false
```

- `full`：true 表示全量重算最近 2 年
- 不传 `trade_date` 默认计算最近 5 个交易日

### 3.4 选股宽表构建

```bash
POST /api/v1/jobs/sync-selection?trade_date=2026-04-30&full=false
```

- 参数同技术因子计算

### 3.5 统一触发（按 job_name 路由）

```bash
POST /api/v1/jobs/run
Content-Type: application/json

{
  "job_name": "daily_kline_sync",
  "biz_date": "2026-04-30",
  "force": false
}
```

支持的 `job_name` 前缀：

| job_name 前缀 | 对应任务 |
|--------------|---------|
| `daily_kline` | 日线同步 |
| `financial` | 财务指标同步 |
| `factor` / `compute` | 技术因子计算 |
| `selection` | 选股宽表构建 |

## 4. 补历史任务

针对单只股票补充历史数据，通过 backfill 接口：

```bash
POST /api/v1/backfill/run
Content-Type: application/json

{
  "symbol": "600519.SH",
  "data_type": "DAILY",
  "start_date": "2020-01-01",
  "end_date": "2024-12-31",
  "force": false
}
```

**`data_type` 可选值**：

| 值 | 说明 | 对应目标表 |
|----|------|-----------|
| `DAILY` | 日线行情 | dwd_stock_daily |
| `FINANCE` | 财务指标 | dwd_stock_financial_indicator |
| `FACTOR` | 技术因子 | dwd_stock_factor_daily |
| `ADJUST_FACTOR` | 复权因子（暂未实现） | dwd_stock_adjust_factor |

查询补历史状态：

```bash
GET /api/v1/backfill/status/{task_id}
```

## 5. 任务状态查看

### 5.1 任务列表

```bash
GET /api/v1/jobs?page=1&page_size=20&status=FAILED&biz_date=2026-04-30
```

### 5.2 任务详情

```bash
GET /api/v1/jobs/{job_id}
```

### 5.3 任务日志

```bash
GET /api/v1/jobs/{job_id}/logs?offset=0&limit=100
```

日志来自 `etl_job_run_log` 表，包含 INFO/WARN/ERROR 级别。

## 6. 定时任务管理

### 6.1 查看定时任务状态

启动服务后，日志中会打印：

```
✅ 定时任务已注册: 股票主数据同步 (周一至周五 18:00 北京时间) + 日线同步 (周一至周五 19:00 北京时间) + 因子计算 (周一至周五 20:30) + 选股宽表 (周一至周五 21:30) + 日志清理 (每天 00:05 北京时间)
```

### 6.2 修改执行时间

编辑 `app/scheduler.py`，调整 `CronTrigger` 参数：

```python
scheduler.add_job(
    func=run_daily_sync,
    trigger=CronTrigger(hour=19, minute=0, day_of_week="0-4", timezone='Asia/Shanghai'),
    #                     ^^^ hour=小时 minute=分 day_of_week=0-4(周一至周五)
    id="daily_stock_sync",
    ...
)
```

### 6.3 禁用定时任务

注释掉对应的 `scheduler.add_job()` 调用即可。

## 7. 日志说明

### 7.1 日志文件

任务执行的日志写入 `/app/logs/` 目录（可通过 `SYNC_LOG_DIR` 环境变量修改）：

```
/app/logs/sync_stock_daily_20260501.log    # 日线同步日志
/app/logs/compute_factor_20260501.log       # 因子计算日志
/app/logs/build_selection_mart_20260501.log # 选股宽表日志
```

### 7.2 数据库日志表

通过 API 查询的日志来自数据库 `etl_job_run_log` 表。日志写入时机：

- 任务创建时
- 批次开始时
- 任务完成时
- 任务失败时

## 8. 断点续传

`sync_stock_daily` 支持断点续传。任务中断后重启，自动从上次位置恢复（通过 `etl_checkpoint` 表记录进度）。

如需强制从头开始：
- 定时任务：修改 `force_restart=True`
- API 触发：`?force_restart=true`
- backfill：请求中 `force: true`
