# 问股策略数据库支持分析报告

> 生成时间：2026-05-04  
> 数据库：stock_cache_system（PostgreSQL @ 192.168.3.16:5432）

---

## 一、概述

本文档分析 `daily_stock_analysis` 项目中 **11 个问股策略** 的数据需求，以及 **本地 PostgreSQL 数据库** 对这些策略的支持程度。

- **完整支持**：9 个策略（仅需本地数据即可运行）
- **部分支持**：2 个策略（需要实时联网数据作为补充）

---

## 二、数据库核心表结构

| 表名 | 说明 | 关键字段 |
|------|------|---------|
| `dwd_stock_daily` | 日线行情 | open/high/low/close/volume/amount/change_pct/turnover_rate/volume_ratio/suspended_flag/is_limit_up/is_limit_down |
| `dwd_stock_factor_daily` | 技术因子（日度） | MA5/10/20/60/120/250、RSI6/14、ATR14、MACD_DIF/DEA/HIST、is_new_high_60d、is_break_ma20、trend_score |
| `dwd_stock_financial_indicator` | 财务指标 | EPS/BPS/ROE/ROA/gross_margin/net_margin/debt_to_asset/revenue_yoy/net_profit_yoy |
| `dwd_security_master` | 股票主数据 | symbol/ticker/name/exchange/industry_l1/industry_l2/area/is_st/status |
| `dwd_board_master` | 板块主表 | board_code/board_name/board_type/parent_board_code |
| `dwd_board_relation` | 股票-板块关系 | symbol/board_code/board_type |
| `dwd_trade_calendar` | 交易日历 | trade_date/is_open/prev_trade_date/next_trade_date |
| `mart_stock_selection_daily` | 选股宽表 | 综合评分/排名/板块/行业汇总字段 |

### 策略 1：底部放量（bottom_volume）

**策略分类**：反转  
**优先级**：60  
**适用市场状态**：trending_down（下跌趋势）

#### 3.1.1 数据需求

| 数据项 | 说明 | 用途 |
|--------|------|------|
| 日线 OHLCV | 最近 30 日 | 判断持续下跌（20日高点到近期低点跌幅 > 15%） |
| 趋势状态 | BEAR 或 STRONG_BEAR | 确认下跌趋势 |
| 量比（volume_ratio） | 当日成交量 / 5日均量 | 检测放量异动（> 3 倍） |
| K 线颜色 | 阳线（收盘 > 开票） | 确认价格企稳 |
| 下影线长度 | 用于判断支撑 | 确认买方支撑 |

#### 3.1.2 数据库支持情况

| 数据项 | 支持表 | 字段 | 支持方式 |
|--------|--------|------|---------|
| 日线 OHLCV | `dwd_stock_daily` | open/high/low/close/volume | ✅ 完整存储，60日历史全覆盖 |
| 趋势状态 | `dwd_stock_factor_daily` | trend_score / MA 排列 | ✅ 通过 MA 排列判断多头/空头 |
| 量比 | `dwd_stock_daily` | volume_ratio | ✅ 字段已存储 |
| K 线颜色 | `dwd_stock_daily` | open/close | ✅ 可计算（close > open = 阳线） |
| 下影线 | `dwd_stock_daily` | high/low/open/close | ✅ 可通过 K 线形态计算 |

#### 3.1.3 支持结论

**✅ 完整支持**

本地数据库可完整覆盖 `底部放量` 策略所需的全部数据需求。Agent 运行时通过 `get_daily_history` 读取日线数据，通过 `analyze_trend` 获取趋势状态和 MA 排列。

### 策略 2：箱体震荡（box_oscillation）

**策略分类**：框架  
**优先级**：50  
**适用市场状态**：sideways（横盘震荡）

#### 3.2.1 数据需求

| 数据项 | 说明 | 用途 |
|--------|------|------|
| 日线 OHLCV | 最近 60~120 日 | 识别箱体顶部和底部（多次触碰高/低点） |
| 支撑/阻力位 | analyze_trend 输出 | 辅助定位箱体边界 |
| 当前价格 | 实时行情 | 判断当前位置（箱底/箱中/箱顶） |
| 量能状态 | 放量/缩量 | 判断支撑/阻力有效性 |
| 箱体宽度 | (顶部-底部)/底部 | 判断操作空间（<5%不建议参与） |

#### 3.2.2 数据库支持情况

| 数据项 | 支持表 | 字段 | 支持方式 |
|--------|--------|------|---------|
| 日线 OHLCV（120日） | `dwd_stock_daily` | open/high/low/close/volume | ✅ 完整存储 |
| 支撑/阻力位 | `dwd_stock_factor_daily` + `analyze_trend` | support_levels / resistance_levels | ✅ analyze_trend 可计算输出 |
| 当前价格 | `dwd_stock_daily` | close（最近一日收盘价） | ⚠️ 仅支持日收盘，实时价需联网 |
| 量能状态 | `dwd_stock_daily` | volume_ratio / turnover_rate | ✅ 字段已存储 |
| 箱体宽度计算 | `dwd_stock_daily` | high/low | ✅ 本地计算 |

#### 3.2.3 支持结论

**✅ 完整支持**

箱体震荡策略的核心是历史日线数据的形态识别，本地数据库完全覆盖。实时价格用于判断当前位置（距支撑/阻力位的距离），可接受使用最近收盘价作为近似。策略判断以形态为主，实时性要求不高。

### 策略 3：默认多头趋势（bull_trend）

**策略分类**：趋势

| 突破量能 | 放量突破日 / 反弹日成交量 | 验证趋势有效性 |
| 止损位 | MA20 下方或结构低点 | 输出交易建议 |

#### 3.3.2 数据库支持情况

| 数据项 | 支持表 | 字段 | 支持方式 |
|--------|--------|------|---------|
| MA5/10/20 排列 | `dwd_stock_factor_daily` | ma5/ma10/ma20 | ✅ 完整存储 |
| MA 斜率 | `dwd_stock_factor_daily` | trend_score | ✅ trend_score 反映趋势强度 |
| 价格与 MA20 乖离 | `dwd_stock_factor_daily` + `analyze_trend` | bias_ma20 | ✅ analyze_trend 输出 |
| 突破量能 | `dwd_stock_daily` | volume_ratio | ✅ 字段已存储 |
| 止损位判断 | `dwd_stock_factor_daily` | ma20 / low | ✅ 本地计算 |

#### 3.3.3 支持结论

**✅ 完整支持**

作为系统的默认策略，数据库设计之初即以此策略的数据需求为首要目标。`dwd_stock_factor_daily` 表完整覆盖了多头趋势判断所需的全部技术指标。

**策略分类**：框架

#### 3.4.1 数据需求

| MACD 指标 | DIF / DEA / HIST | 背驰判断（顶背驰/底背驰） |
| 当前价格 | 实时行情 | 判断当前所处买卖点 |
| 买卖点类型 | 一买/二买/三买/一卖/二卖/三卖 | 输出交易建议 |

#### 3.4.2 数据库支持情况

| 数据项 | 支持表 | 字段 | 支持方式 |
|--------|--------|------|---------|
| 日线 OHLCV（60日） | `dwd_stock_daily` | open/high/low/close | ✅ 完整存储 |
| MACD 指标 | `dwd_stock_factor_daily` | macd_dif/macd_dea/macd_hist | ✅ 完整存储 |

#### 3.4.3 支持结论

**✅ 完整支持**

缠论的核心是价格形态（分型→笔→线段→中枢）和 MACD 背驰判断，两者均基于日线数据。本地数据库的日线表和技术因子表可完整支持缠论分析。实时价格用于确认当前位置，但缠论本质是形态分析，对实时性要求有限。
