# 前端开发流程手册

> 本文档描述如何推进开发工作，不描述具体任务。
> 具体任务清单 → `开发计划.md`
> 具体任务位置 → 各目录 README.md

---

## 一、文档体系

```
front_ui/
├── README.md          ← 项目总览（新人读一次）
├── 开发计划.md          ← 任务总清单（了解全貌时读）
└── 开发流程.md          ← 流程手册（本文，每次新会话读这里）
```

### 协作规则

| 时机 | 读什么 |
|------|--------|
| 新会话启动 | 开发流程.md（第 2-3 节） |
| 了解有哪些任务 | 开发计划.md |
| 找某个任务在哪个文件 | 对应目录的 README.md |
| 不知道某个文件干什么 | 对应目录的 README.md |
| 完成了某个任务 | 按「五、收尾动作」更新 README |

## 二、新会话启动流程

```
Step 1：读本节
Step 2：打开开发计划.md，确认当前阶段
Step 3：根据阶段打开对应目录 README.md，确认具体任务位置
Step 4：打开目标文件，开始工作
```

### Step 1：本节（现在在这里）

确认项目位置：
```
/home/coco/.openclaw/workspace-coding/agent_work/stock_project/front_ui/
```
启动命令：`npm run dev`（端口 5173）

### Step 2：读 `开发计划.md`

找到「当前阶段」，确认：
- 正在做哪个 Phase
- Phase 下一步要做什么

### Step 3：读对应目录 README.md

根据任务类型，找到任务所在的文件：

| 任务类型 | 读哪个 README |
|---------|--------------|
| API 相关（新增/修改接口） | `src/api/README.md` |
| Store 相关（状态管理） | `src/stores/README.md` |
| Type 定义（类型/接口） | `src/types/README.md` |
| 页面组件（路由页面） | `src/pages/README.md` |
| 业务组件（可复用组件） | `src/components/README.md` |
| 布局/样式 | `src/layouts/README.md` / `src/assets/README.md` |
| 工具函数 | `src/utils/README.md` |

### Step 4：开始工作

打开目标文件，按代码本身实现功能。

## 三、日常开发标准流程

### 阶段 A：接任务

1. 从 `开发计划.md` 选一个 P0 任务
2. 确认该任务在哪个文件（读对应 README）
3. 理解任务需求（看 `开发计划.md` 里任务描述）

### 阶段 B：写代码

按以下依赖顺序开发：

```
Type 类型定义
    ↓
API 方法（调后端）
    ↓
Store 状态（可选）
    ↓
页面/组件（用上面三样）
```

### 阶段 C：自测

```bash
npm run dev
# 浏览器打开 http://localhost:5173
# 确认功能正常
```

### 阶段 D：收尾（完成后必做）

完成一个任务后，必须更新文档：

| 改了/新增了什么 | 必须更新 |
|---------------|---------|
| API 方法 | `src/api/README.md` |
| Store | `src/stores/README.md` |
| Type | `src/types/README.md` |
| 页面组件 | `src/pages/README.md` |
| 业务组件 | `src/components/README.md` |
| 目录结构 | `front_ui/README.md` |
| 任务状态/新增任务 | `开发计划.md` |

## 四、遇到问题时的流程

### 问题：不知道某个 API 怎么调用

```
→ 读 src/api/README.md，找到对应模块
→ 看方法名、参数、返回值
→ 对应实现代码在 src/api/xxx.ts
```

### 问题：不知道某个 Type 怎么定义

```
→ 读 src/types/README.md
→ 看对应的类型文件（如 stock.ts）
→ 参照已有定义格式
```

### 问题：不知道某个页面在哪个文件

```
→ 读 src/pages/README.md
→ 找对应页面的文件路径
```

### 问题：页面报错找不到接口

```
→ 先确认后端是否完成（Phase 2.3 有 Mock 方案）
→ 查看 vite.config.ts 代理配置
→ 查看 src/api/request.ts 拦截器
```

### 问题：Lightweight-charts K 线图集成

```
→ 先做 Phase 3.2.1 KLineChart.vue 组件
→ 组件完成后再做 Phase 4 的 StockDetailPage K 线部分
```

## 五、文档更新规则

> **核心原则：代码改了，README 必须跟着改。新会话看到的 README 必须是最新状态。**

### 何时更新 README

只要做了以下任何一件事，就必须更新对应 README：

| 操作 | 更新哪个 README | 更新内容 |
|------|---------------|---------|
| 新增 API 方法 | `src/api/README.md` | 添加方法说明 |
| 新增 Store | `src/stores/README.md` | 添加 Store 说明 |
| 新增 Type | `src/types/README.md` | 添加类型说明 |
| 新增页面 | `src/pages/README.md` | 添加页面说明 |
| 新增组件 | `src/components/README.md` | 添加组件说明 |
| 改目录结构 | `front_ui/README.md` | 更新目录树 |

### 如何更新 README

每个 README 都有固定格式，找到对应位置，按格式补充：

```markdown
### 方法名
- 说明
- 参数：
- 返回值：
```

### 何时更新开发计划

- 完成了一个任务 → 把状态从 📋 改为 ✅
- 开始新 Phase → 更新「当前阶段」
- 新增任务 → 追加到对应 Phase
